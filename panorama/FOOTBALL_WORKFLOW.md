# 축구 공 추적 편집

[공통 절차](WORKFLOW.md)에서 입력을 확인한다. 이미 스티칭된 파노라마는 바로 아래 1절에서 시작한다. 좌우 원본을 사용할 때는 시간과 접합부를 먼저 맞춘다. [축구 프로필](profiles/football.json)의 기본 출력은 쿼터별 1080p 16:9, 30fps, 원본 경기 소리다. 실제 경기 시작점은 쿼터마다 확인한다. 쿼터가 바뀌면 이전 카메라 중심·속도와 공 추적 상태를 초기화한다.

## 1. 파노라마에서 공의 경로를 읽는다

잘라내기 전의 파노라마를 먼저 훑어 킥오프, 정지 후 재개, 긴 패스, 터치라인 접근, 시야에서 사라지는 구간을 표시한다. 움직이는 작은 물체 탐지나 선수 밀집도는 후보를 찾는 데 쓴다. 선수 발밑에 공과 비슷한 색의 물체가 있으면 원본에서 킥 직전부터 수신까지 이어서 본다. 한 후보는 발걸음마다 같은 발끝에 붙어 있고 다른 후보는 발에서 떨어져 반대편 선수에게 도착하면 후자를 공으로 기록한다. 드리블 중에는 공과 신발이 겹칠 수 있으므로 다음 터치에서 둘이 분리되는 순간까지 확인한다.

로컬 관측 기록의 머리에는 **자르기 전 파노라마의 기준 시각, 좌표 원점, 가로·세로 크기**를 쓴다. 한 지점마다 시각 또는 PTS, 확인한 영상, 상태, 근거를 남긴다. 공 전체가 보이면 테두리 상자 `[left, top, right, bottom]`도 기록한다. 관측 파일은 경기 양식의 `ball_review`에서 가리킨다.

| 상태 | 기록과 화면 처리 |
|---|---|
| 공이 보임 | 확인한 위치·크기를 기록한다. 기존 편집 화면 밖에서 찾은 공도 새 경로에 반영한다. |
| 잠시 가려짐 | 마지막 관측과 재등장 시각을 표시한다. 가려진 동안은 주변 플레이가 보이는 구도를 유지하고, 재등장한 공을 확인해 추적을 잇는다. |
| 위치 불확실 | 후보가 여럿이거나 프레임 사이의 경로만 추정할 수 있으면 근거와 불확실 구간을 표시한다. 예상 수신자 쪽으로 갑자기 줌인하지 않는다. |
| 원본 촬영 경계에서 잘림 | 입력 파노라마의 전체 화면에서 공 일부가 보이는지, 완전히 사라졌는지 기록한다. 좌우 원본으로 작업 중이면 양쪽 화면도 확인한다. 원본에는 온전한데 편집 화면에서 잘린 경우는 크롭 보정 대상으로 둔다. |

보통 속도의 패스는 흐름을 파악할 간격으로 검토하고, 방향이 급변하거나 공이 경계에 닿는 구간에서는 출력 한 프레임씩 앞뒤로 확인한다. 이미 놓친 공을 찾을 때는 기존 크롭의 검색 범위를 전체 파노라마로 넓힌다.

## 2. 관측을 따라 화면 경로를 만든다

프레임마다 파노라마 픽셀 기준의 중심 `(cx, cy)`와 폭 `w`를 계획한다. 16:9 크롭의 높이는 `w × 9 / 16`이다. 공이 충분히 안쪽에 있고 짧은 드리블만 이어질 때는 구도를 유지해 작은 움직임마다 화면이 흔들리는 일을 줄인다. 긴 패스는 출발과 도착 사이의 실제 관측을 더 찍고 그 구간에서 화면 이동을 빠르게 한다.

중심과 폭을 **시간 구간 전체에서 함께** 부드럽게 조정한다. 예를 들어 출발·비행·착지에 키프레임을 두고, 위치와 줌의 변화 속도가 양끝에서 이어지도록 보간한다. 정지 후 재개 구간에서는 킥 전 구도를 고정한다. 미래의 도착점이 고정 구간에 영향을 주면 출발 시점에서 구간을 나눠 다시 계산한다. 출력 크롭이 원본 유효 영역에 드는지와 실제 공을 담는지는 별개로 확인한다.

**롱킥 예시.** 골키퍼가 공을 내려놓고 뒤로 물러서는 장면에서 공격수가 먼저 달려가더라도 키커와 공을 담는다. 발 접촉 직전과 공이 발에서 떨어져 이동하는 첫 프레임을 표시한다. 그 뒤 공이 높이 뜨면 수평 이동뿐 아니라 화면 높이도 따라간다. 도착 순간 공이 늦게 들어오면 비행 중간의 관측과 카메라 이동 속도를 수정한다. 킥 전 정지 구간과 착지 후 구도까지 이어서 재생하면 조기 이동과 늦은 추종을 함께 확인할 수 있다.

**가장자리 예시.** 가까운 터치라인에서는 공 중심이 안에 있어도 아래쪽이 잘릴 수 있다. 공 상자와 크롭의 왼쪽·위·오른쪽·아래를 같은 좌표계로 놓고 각 변의 안쪽 여유를 계산한다. 예를 들어 아래쪽 여유는 `crop_bottom - ball_bottom`이다. 음수면 공 일부가 잘린다. 경계 접근 전후만 조금 넓혀 여유를 만들고 부드럽게 복귀한다. 넓힌 구도가 투영의 빈 영역에 걸리면 중심도 함께 조정한다. 가능한 구도로도 모두 담기 어려운 부분은 그 시각과 원인을 남긴다.

## 3. 이상 구간을 찾고 고친다

| 재생 중 보이는 문제 | 확인할 근거와 수정 방법 |
|---|---|
| 공은 왼쪽으로 갔는데 화면이 선수 무리를 따라 오른쪽으로 간다 | 전체 파노라마에서 마지막 확실한 공부터 다시 읽는다. 관측과 추정을 구별하고 잘못된 목표를 교체한 뒤 경로를 다시 만든다. |
| 롱킥은 따라가지만 화면이 몇 번씩 꺾인다 | 프레임별 중심·폭의 변화량을 살피고 속도·가속도가 갑자기 튀는 곳을 찾는다. 잘린 프레임 하나만 밀어 넣지 말고 앞뒤 구간을 함께 수정해 양끝의 위치와 속도를 잇는다. |
| 공이 접합부를 지날 때 두 개로 보이거나 순간이동한다 | 기존 파노라마에서는 접합부 전후에 분명히 보이는 공을 기준으로 구도를 잇고 판독이 어려운 시각을 남긴다. 좌우 원본으로 작업 중이면 시간·공간 정렬을 확인하고 보정한 뒤 공 위치를 다시 확인한다. |
| 공을 잃자 곧바로 먼 곳에 줌인한다 | 가려진 시간에 들어간 추정 좌표를 확인한다. 마지막 플레이 구도를 유지하거나 조금 넓히고, 실제 재포착 프레임부터 자연스럽게 따라간다. |

### 기존 편집본의 부분 보정

- 쿼터별로 사용자가 마지막으로 본 편집본, 그 크롭 경로, 원본을 맞춘다. 파일이 이동하거나 이름이 바뀌었으면 저장된 영상 정보와 같은 시각의 장면으로 대응을 확인한다. 출력 타임코드에 원본 트림 시작점을 반영해 같은 패스를 비교한다.
- 같은 오추적을 다른 쿼터에서도 찾아 달라는 요청이면 지정된 각 쿼터의 전체 시간축을 훑는다. 전체 파노라마에 기존 크롭 경계를 겹쳐 보고, 패스 뒤 화면이 키커에게 되돌아가거나 한쪽에 머무는 구간을 찾는다. 검출이 끊긴 동안에도 반대편으로 넘어간 공을 놓칠 수 있다. 빠른 패스는 원본을 프레임 단위로 살펴 공이 떠난 순간과 도착한 순간을 찾고, 각 순간에 신발이 어디에 있었는지 대조한다.
- 신발이 후보로 잡혀도 화면이 패스와 수신을 잘 담으면 기존 구도를 유지한다. 화면이 신발 쪽으로 벗어난 구간은 기존 줌 폭에서 패닝을 먼저 고친다. 가장자리 줌아웃을 요청받으면 원본에서 온전히 보이는 공의 윤곽이 크롭에 닿는 구간만 필요한 만큼 넓힌다. 투영 경계가 휘어 있는 곳은 실제 출력에서도 공 전체가 보이는지 확인한다.
- 마지막으로 구도가 맞았던 프레임과 다시 맞아지는 프레임 사이에서 경로를 부드럽게 잇는다. 보정 전후를 같은 출력 타임코드로 재생하고, 전환부를 포함한 수정 구간 밖의 크롭 경로와 앞선 가장자리 보정이 유지됐는지 대조한다. 다른 원인으로 남은 문제는 해당 시각과 함께 기록한다. 검토만 한 쿼터는 기존 파일을 안내한다.

## 4. 쿼터별 완료 판단

- 실제 시작 장면과 출력 0초, 오디오 시작이 일치하는지 확인한다. 프레임별 크롭 경로와 영상에 트림을 한 번씩 같은 기준으로 적용한다.
- 전체 출력 프레임에서 크롭 비율·유효 촬영 영역·중심과 폭의 연속성을 검사한다. 직접 관측한 공 상자에서 네 변의 여유를 계산하고, 가장 낮은 여유·빠른 이동·줌 전환 구간을 출력 영상에서 재생한다.
- 공을 차기 전부터 도착 후까지, 가림 직전부터 재포착 이후까지 **연속 재생**한다. 정지 화면만 확인하면 공은 매번 보이는데 카메라가 먼저 움직이거나 튀는 오류를 놓칠 수 있다.
- 쿼터별 `qa.ball_identity`에는 확인한 범위와 결과를 적는다. 혼동 후보가 있었으면 해당 출력 타임코드와 판정 근거를 적거나 상세 검수 기록을 연결한다. 부분 보정이면 실제로 바꾼 구간도 함께 적는다.
- 결과 파일의 전체 디코딩과 음성 검사를 마치고 쿼터별 양식의 `qa`를 갱신한다. 남은 문제에는 **트림 후 시각, 원본에서 보인 정도, 결과에서 잘린 정도, 시도한 보정**을 적는다. 표본 기반의 공 관측 수와 전체 프레임 검사 수는 구분해 보고한다.

팀·장소·날짜는 해당 경기에서 확인한 값으로 제목과 설명에 넣는다. 상세 관측, 경기별 코드·카메라 경로와 검수 기록은 작업 폴더에 보존한다.
