# 파노라마 스티칭과 추적 뷰 편집

요청한 결과가 원본 짝 확인, 전체 파노라마, 추적 편집 중 어디까지인지 먼저 정한다. [공통 절차](../../../panorama/WORKFLOW.md)와 [기본 설정](../../../panorama/presets/default.json)을 기준으로 작업한다. 일반 촬영은 [촬영 양식](../../../panorama/templates/job.json), 축구는 [경기 양식](../../../panorama/templates/match.json)을 저장소의 `work/<작업명>/`에 복사한다. 작업을 이어받을 때는 기존 기록에서 사용한 입력·시간축·크롭 좌표계를 확인한다.

## 입력에서 시작 단계 고르기

- 지정된 파일과 폴더의 하위 영상까지 목록에 넣고 초·중·후반을 확인한다. 카메라 원본은 같은 동작이 양쪽에 나타난 시각과 시야로 짝을 확인한다. 한쪽만 분할 녹화됐으면 파일별로 겹치는 구간을 기록한다. 누락·손상·판단 보류는 편집 전에 파일명, 근거, 영향을 받는 구간과 함께 알린다. 짝 확인만 요청받았다면 이 결과를 전달한다.
- **좌우 원본을 스티칭할 때**는 촬영마다 시간차·드리프트·공간 보정을 측정한다. [프레임 스티칭 도구](../../../panorama/tools/stitch_frames.py)로 정지 배경과 움직이는 대상이 접합부에서 이어지는지 확인한 뒤 전체 영상을 렌더한다. 전체 파노라마 요청은 사용자가 지정한 시야와 여백을 보존한다.
- **기존 파노라마의 추적 뷰를 만들 때**는 그 파일의 전체 프레임과 시간축에서 바로 관측과 크롭을 시작한다. 같은 구간의 좌우 원본도 함께 있으면 기존 파노라마를 사용한다. 혼합 입력은 구간별로 이 결정을 내린다.
- **기존 축구 편집본의 오추적·잘림을 다시 볼 때**는 해당 쿼터의 최신 편집본과 그때 사용한 파노라마를 짝지어 [부분 보정 절차](../../../panorama/FOOTBALL_WORKFLOW.md#기존-편집본의-부분-보정)를 적용한다. 새 보정본은 이번 작업의 출력 폴더에 둔다.

## 추적과 완료 판단

축구 공 추적은 [축구 편집 절차](../../../panorama/FOOTBALL_WORKFLOW.md)와 [축구 프로필](../../../panorama/profiles/football.json)을 적용한다. 쿼터별 시작점을 확인하고 추적 상태를 초기화한다. 롱킥은 실제 출발부터 빠르게 따라가고, 가려진 동안에는 마지막 플레이를 담다가 공이 다시 관측되면 추적을 잇는다. 가장자리에서 공 전체가 잘릴 때만 살짝 줌아웃하고 부드럽게 복귀한다. 다른 피사체를 추적할 때는 요청한 대상과 출력 비율을 기준으로 경로를 정한다.

대표 장면은 실제 재생 속도로 확인한다. 최종본에서는 전체 디코딩, 유효 촬영 영역, 패닝·줌의 연속성, 음성 싱크를 검사한다. [오디오 검사 도구](../../../panorama/tools/verify_audio.py)의 기준 시각과 실행 예시는 [도구 사용법](../../../README.md)에 있다. 관측·촬영별 코드·검수 기록은 작업 폴더에, 완성한 영상은 `outputs/<작업명>/`에 둔다. 직접 재생한 구간과 남은 잘림·접합 오류는 출력 타임코드로 전달한다.
